# Использование ИИ

**Использовал ли ИИ:** да, Claude (Claude Code).

## Для каких частей задания

- **Выбор библиотеки:** сравнение кандидатов (Ktor Client, Koin, Coil, kotlinx.serialization, Koog), выбор Koin и механизма резолвинга.
- **Поиск в исходниках:** поиск классов и методов, через которые проходит `get()` в Koin 4.2.2, номера строк для точек останова.
- **Объяснение механизма:** разбор цепочки `Koin → Scope → CoreResolverV2 → InstanceRegistry → InstanceFactory`.
- **Демо-проект:** код (`Classes.kt`, `AppModule.kt`, `Main.kt`), настройка Gradle и README.
- **Диаграммы:** UML-диаграммы пакетов, классов и последовательности (`koin_diagrams.drawio`).
- **Презентация:** структура, тексты слайдов, анализ проектных решений, фрагменты кода.

## Что создано или существенно переработано с помощью ИИ

- Демо-проект написан ИИ целиком.
- Диаграммы построены ИИ по исходникам Koin 4.2.2, затем проверены и поправлены.
- Презентация (тексты и вёрстка) подготовлена ИИ.

## Как проверял результат

- Каждый класс, поле, метод и связь на диаграммах сверены с исходниками тега 4.2.2.
  Номера строк, указанные в README и на слайдах, проверены по файлам этой версии.
- Демо собрано и запущено (`./gradlew run`); вывод всех шести сценариев совпадает с ожидаемым
  поведением `single`, `factory`, `scoped`, квалификаторов и параметров.
- В режиме `--args=debug` логи Koin подтверждают ключи реестра (`класс:квалификатор:скоуп`)
  и порядок шагов резолвинга.
- Утверждения об API, которые ИИ использовал в анализе (`allowOverride` по умолчанию `true`,
  `Koin.addResolutionExtension`, `Module.verify()` в koin-test, `@KoinInternalApi` у `indexPrimaryType`,
  `unloadModules`), проверены по исходному коду. Одно неверное утверждение ИИ (что дублирование
  ключа без квалификатора роняет старт) найдено при проверке и исправлено.
